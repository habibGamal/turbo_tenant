# Live account browser tests

Run `npm run test:e2e:auth` after installing dependencies, building the current storefront (`npm run build`), and provisioning the existing migrated `e2e.localhost` tenant with the `E2eSeeder` location fixtures. No migration or seeding is performed by this suite. The local Laravel/MySQL configuration must be usable and `php` must be on PATH.

Each test starts its own loopback-only PHP server on an available port with its own cache prefix. Real throttling remains active inside each test. The server refuses other hosts, environments outside local/testing, and tenant IDs other than `e2e`. Real password-reset notifications use Laravel's log mailer pointed to a newly created private temporary directory. The server changes no tenant mail setting; its temporary mail capture is removed after the test. Screenshots, videos and traces are disabled in the recovery spec to avoid storing reset links. Do not publish temporary mail files or browser logs containing reset URLs.

The fixture creates uniquely named non-admin customers and deletes only the exact test-owned emails and associated addresses/reset rows. It never resets the tenant or modifies the shared `admin@example.com` fixture. The profile phone test is explicitly expected to fail: the screen submits phone but the current profile request/controller do not persist it. Login via Google is covered only up to the local handoff link; no external account is used. Verification and account deletion have no supported React screens. Profile logout may navigate to either home or the login redirect because the profile guard and logout navigation race; the suite checks that the real logout request succeeds and the customer is signed out.

Stopping the process forcibly may prevent fixture teardown; if that happens, inspect and remove only the specific owned `auth-e2e-<uuid>@example.test` users and temporary directory for the interrupted run. Do not truncate tables or reset shared settings.
